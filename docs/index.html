deepseek-tui

A terminal UI for the DeepSeek Harness (dsh). It runs the harness as a subprocess over stdio JSON-RPC and renders the live session event stream — a thin, fast client over a fully plugin-composed agent runtime.

How it fits together

The TUI owns no agent logic. It spawns the harness, talks to it over a JSON-RPC channel on stdout, and turns the resulting event stream into a terminal interface. Everything the agent can do is decided by the harness composition in cordis.yml.

Deliberately not mounted

  • dsh-subagent-dsh-sdk, dsh-subagent-acp — need a second runtime / ACP agent
  • dsh-web-search-exa, dsh-web-search-perplexity — need API keys
  • dsh-tool-pwsh, dsh-pwsh-*, dsh-sandbox-windows-acl — Windows only
  • dsh-tool-cordis — dynamic code reaches the real runtime; opt-in by design
  • dsh-tool-bash-persistent — superseded by the terminal tools
  • dsh-fs-local, dsh-bash-local — replaced by their sandbox equivalents
  • types-only / abstract bases — mounting them fails to load

Under the hood

  • Sandbox — dsh-fs-sandbox + dsh-bash-sandbox confine writes and commands; default workspace-write
  • Delegation — in-process subagents, plus real Claude Code / Codex CLIs as genuinely different agents
  • MCP — one row per server; context7 ships wired up, degrades gracefully on failure
  • Skills — from .dsh/skills/<name>/SKILL.md
  • Hooks — Claude-Code format from .claude/settings.json, Codex format from $CODEX_HOME/config.toml
  • Compaction — qwen3.6-flash summarizer, threshold 0.4 / retain 0.16

Get running

Needs Bun, Node.js, pnpm and git. The installer fetches and builds the harness next door, installs the app, and checks it works.

# 1. install (a few minutes the first time, mostly building)
git clone https://github.com/Cass67/deepseek-tui.git
cd deepseek-tui
node scripts/install.mjs

# 2. run — the launcher keeps your cwd as the agent workspace
./bin/deepseek-tui

Environment

  • DSH_PROVIDER / DSH_MODEL — pin the route (overrides the remembered one)
  • DSH_MAX_TOKENS — output cap per turn (default 16384)
  • DSH_CWD — agent workspace (defaults to the launcher's cwd)
  • LOCAL_LLM_BASE_URL — endpoint for the local router route
  • CONTEXT7_API_KEY — raises context7 rate limits (optional)

Health checks

  • node scripts/install.mjs --check — harness present, correct, built?
  • node scripts/preflight.mjs — does the harness answer the L2 methods this app calls?
  • node scripts/tool-audit.mjs — which tools actually register (reads the schemas sent to the model)
  • node scripts/tool-exec-check.mjs — tools genuinely execute, incl. a sandbox refusal that must fail
  • bunx tsc --noEmit · bun test · bun run build
Against the upstream harness the app starts and then fails as soon as anything reads settings — the settings overlay, both pickers, and last-model-restore. That's the symptom of the wrong harness, not a bug in the TUI.
